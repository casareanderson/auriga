Drive the Chrome you already use, from any local tool or AI agent.

Auriga is a small Chrome extension, a stdlib-only Python bridge and a tiny CLI that let a script or model control your real browser — same tabs, same logins, same session. No MCP server, no native messaging host, no telemetry.

Get started View source (AGPL-3.0)

What it does

Any program that can make an HTTP call can drive the browser. The bridge listens on 127.0.0.1 only and the extension long-polls it, so nothing is exposed to the network and nothing leaves the machine.

  • List open tabs with their id, title, url and active state.
  • Navigate, click elements by CSS selector, type into fields, and read page text.
  • Run JavaScript in a page and read back the result.
  • Take PNG screenshots of the active tab.
  • Build an accessibility tree with numeric refs, then click precisely by ref.
  • Click or hover at raw screen coordinates (canvas drawings, unlabelled icons).
  • Upload files into inputs across all frames via the Chrome DevTools Protocol.
  • Capture console output, network responses and failures for debugging.
  • List, read, create and delete cookies for the active tab's origin.

Install

Linux or macOS. The whole thing is local; there is nothing to sign up for.

# 1. Clone the repository
git clone https://github.com/casareanderson/auriga && cd auriga

# 2. Run the setup script (makes scripts executable, creates ~/.auriga/config.json)
./install.sh

# 3. Load the extension
#    chrome://extensions → Developer mode → Load unpacked → select the extension/ directory

# 4. Start the bridge (keep it running)
python3 auriga.py

# 5. Smoke-test it
./auriga tabs

Full instructions, including the optional shared token, audit log and failure alerts, are in the README.

Usage

The CLI wraps a plain HTTP API on 127.0.0.1:8765:

./auriga tabs                                   # list tabs
./auriga navigate "https://example.com"        # navigate the active tab
./auriga click "#login-button"                 # click by CSS selector
./auriga type "input[name=email]" "me@x.com"   # type into a field
./auriga read                                  # dump the active tab's text
./auriga eval "document.title"                 # run JS in the page
./auriga screenshot out.png                    # screenshot the active tab
./auriga upload "~/Downloads/file.pdf"         # set a file input via CDP
./auriga snapshot                              # accessibility tree with refs
./auriga click-ref 12345                       # click by ref from snapshot
./auriga capture both 5                        # capture console + network for 5s

Drive it from anything that can make an HTTP request:

curl -s -X POST http://127.0.0.1:8765/command \
  -H 'Content-Type: application/json' \
  -d '{"action":"type","selector":"input[name=q]","text":"hello"}'

Security model

Auriga's security posture is the point, not an afterthought:

  • Loopback-only — the bridge binds 127.0.0.1; nothing on the network can reach it.
  • Per-site approval — nothing runs on a site until you click "Allow" in the popup.
  • CSRF-protected — a page in another tab cannot talk to the bridge.
  • No cloud, no telemetry — everything stays on the machine.
  • Local audit log — secrets (typed text, JS, cookie values) are redacted before they are written.
Be careful driving pages that spend money. The CLI does exactly what you tell it, including clicking checkout and order buttons.

Status and roadmap

Working today: tabs, navigate, click, type, read, eval, screenshot, cookies, upload (CDP, including iframes), snapshot + click-ref, click-xy / hover, console/network capture, installed-extension listing. In progress: annotated screenshots for vision models, streaming chat / side panel, live remote view. This is an early, honest prototype — some sites resist it.
